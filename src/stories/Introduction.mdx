# MapRoulette Design System

This Storybook documents the reusable UI primitives behind MapRoulette's v4 frontend — the
React 19 + Vite + Tailwind rewrite. Use it to browse components in isolation, check their
variants, and keep the app visually consistent as it grows.

## Tech stack

- **React 19** with **TypeScript**
- **Tailwind CSS v4** — CSS-first config (no `tailwind.config.js`), theming via `@theme` in `src/main.css`
- **Radix UI** primitives + **class-variance-authority** for variant styling
- **TanStack Router** / **TanStack Query** for routing and data
- **Biome** for linting and formatting

## How this is organized

Every component under `src/components/ui/` has a colocated `Component.stories.tsx` file. Stories
are grounded in how each component is actually used elsewhere in the app rather than invented
examples — check a story's `render` function to see a realistic composition.

This currently covers the `ui/` primitive layer only. Extending stories to the larger
feature-level components in `Pages/` and `shared/`, and a broader pass to DRY out duplicated
markup across the app, are tracked as follow-up work.

## Colors

The palette lives in `src/styles/palette.css`: `steel`, a navy-tinted neutral scale, plus
`mint`, `teal`, `ocean`, `lilac`, `mango`, `coral` and `sand`, after MapRoulette v3's colors.
Tailwind's default colors are switched off, so `zinc-*`, `blue-*` and the like don't exist.

Components mostly use the semantic colors defined in `src/main.css`, which adapt to dark mode on
their own, so they need no `dark:` variants:

- **Surfaces:** `page`, `panel` for large regions like sidebars, `card` for items, `inset`,
  `field`, `popover` for anything floating (always opaque), and `muted` / `muted-strong` for
  hover and selection fills
- **Text:** `fg`, `fg-muted`, `fg-subtle`, `link` and `highlight`
- **Lines:** `line`, `line-strong` and `ring`
- **Brand:** `primary` for main buttons and `accent` for selected states and go-ahead buttons
- **Feedback:** `success`, `warning` and `danger`
- **Task statuses:** `status-fixed`, `status-too-hard` and so on

Use palette classes directly only for color that carries meaning of its own. Things in the page
flow are flat with a border; only floating things get a shadow. **Foundation/Palette** shows all
of these.

Storybook's own chrome takes its brand colors and font from `design-tokens/`, compiled by
`npm run tokens:build` ([Style Dictionary](https://styledictionary.com/)) into
`src/styles/tokens.gen.*`.

## Dark mode

Toggle the moon icon in the toolbar above to preview components in dark mode. It flips the same
`.dark` class on `<html>` that the real app's theme switcher uses, so what you see here matches
production.
